# Synthetic cardiology 835 fixtures

Every file in this folder is **entirely synthetic**: fabricated patient names,
member IDs, claim/control numbers and dollar amounts. `ISA06` (interchange
sender ID) literally spells `SYNTHETICNIMBIR` and every file name is prefixed
`synthetic-` so neither a human nor a script can mistake one for a real
remittance. They model a US outpatient cardiology billing office, which is
Nimbir's target buyer — see `D-nimbir-835-dropin`.

Generated by `_gen.py` in this folder (not shipped to the app; run
`python3 _gen.py` to regenerate). The generator builds each segment from an
element list joined with `*`, so delimiter counts are never hand-typed/hand-
counted, which is where EDI fixtures usually get subtly corrupted.

## CARC/RARC wording verified against x12.org (2026-10-05)

Nimbir's build only claims to know the meaning of the six codes these
fixtures actually use. `app/x12/carc-rarc.js` carries this same table; a code
outside this list renders with an honest "not independently verified" note in
the UI rather than an invented description (see
`app/x12/to-nimbir.test.js`, "a CARC code outside the verified list never
gets an invented description").

Source pages fetched 2026-10-05:
- https://x12.org/codes/claim-adjustment-reason-codes (CARC 1, 4, 45, 50, 97)
- https://x12.org/codes/remittance-advice-remark-codes (RARC N115)

| Code | Group | Description (verbatim from x12.org) |
|---|---|---|
| `1` | PR | Deductible Amount |
| `4` | CO | The procedure code is inconsistent with the modifier used. Usage: Refer to the 835 Healthcare Policy Identification Segment (loop 2110 Service Payment Information REF), if present. |
| `45` | CO or PR | Charge exceeds fee schedule/maximum allowable or contracted/legislated fee arrangement. Usage: This adjustment amount cannot equal the total service or claim charge amount; and must not duplicate provider adjustment amounts (payments and contractual reductions) that have resulted from prior payer(s) adjudication. (Use only with Group Codes PR or CO depending upon liability) |
| `50` | CO | These are non-covered services because this is not deemed a 'medical necessity' by the payer. |
| `97` | CO | The benefit for this service is included in the payment/allowance for another service/procedure that has already been adjudicated. Usage: Refer to the 835 Healthcare Policy Identification Segment (loop 2110 Service Payment Information REF), if present. |
| `N115` | RARC | This decision was based on a Local Coverage Determination (LCD). An LCD provides a guide to assist in determining whether a particular item or service is covered. A copy of this policy is available at www.cms.gov/mcd, or if you do not have web access, you may contact the contractor to request a copy of the LCD. |

One correction worth flagging explicitly: a plausible-sounding but wrong
guess for N115 would be "National Coverage Determination" (an NCD is a
separate, CMS-national concept) — the actual x12.org text is **Local**
Coverage Determination. This is exactly the failure mode the verified-only
lookup table in `carc-rarc.js` exists to prevent for every other code a real
uploaded 835 might contain.

`PLB03-1` (e.g. `WO` for Overpayment Recovery, used in
`synthetic-cardio-reversal.835`) is drawn from a separate PLB reason-code list,
not the CARC/RARC pages above, and was **not** independently verified against
x12.org in this pass — it is shown as a raw code in the UI, consistent with
the same "don't invent a description" rule.
